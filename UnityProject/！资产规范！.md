# GameMain —— 项目内容根目录

《泡涌》的**所有自有资源和代码**都放在这个目录下。

> **一条铁律**：第三方插件（Asset Store 下载的、GitHub 拿的）一律放 `Assets/ThirdParty/`，**不要混进 GameMain**。
> 这样出问题时能一眼看出"这是我们的东西还是别人的东西"，升级插件也不会误伤自己的代码。

## 目录总览

```
Assets/
├── GameMain/                  ← 项目自有内容，平时就在这干活
│   ├── Art/                   美术资源
│   ├── Audio/                 音频
│   ├── Data/                  配置数据
│   ├── Prefabs/               预制体
│   ├── Scenes/                场景
│   ├── Scripts/               代码
│   └── UI/                    界面资源
├── Settings/                  URP 渲染管线配置（Unity 模板生成，别乱动）
└── ThirdParty/                第三方插件
```

## 美术资源 `Art/`

| 目录 | 放什么 | 常见格式 |
|------|--------|---------|
| `Models/` | 3D 模型：泡泡、主角、场景块、道具 | `.fbx` `.obj` |
| `Materials/` | 材质球（`Material`） | `.mat` |
| `Textures/` | 贴图：颜色、法线、遮罩、天空盒 | `.png` `.tga` `.exr` |
| `Shaders/` | 着色器：URP Shader Graph、自定义 `.shader` | `.shadergraph` `.shader` |
| `Animations/` | 动画剪辑与动画控制器 | `.anim` `.controller` |
| `VFX/` | 特效：粒子系统、Visual Effect Graph | `.prefab` `.vfx` |
| `Fonts/` | 字体（含 TextMeshPro 字体资源） | `.ttf` `.otf` `.asset` |

**美术同学注意**：模型和贴图**分开放**。不要把 `.fbx` 和它的贴图塞在同一个文件夹里——模型导出时 Unity 会按 `Materials/` 和 `Textures/` 的约定去找，混放会导致材质丢失。

## 界面资源 `UI/`

| 目录 | 放什么 |
|------|--------|
| `Forms/` | 界面预制体（一个界面 = 一个 Prefab） |
| `Sprites/` | UI 图片、图标、九宫格切图 |
| `Atlas/` | 图集（Sprite Atlas） |

**为什么 UI 图片不放在 `Art/Textures/`**：UI 图需要图集打包、九宫格设置、不同的压缩格式，跟 3D 贴图的处理方式完全不同。分开才好批量设置。

## 音频 `Audio/`

| 目录 | 放什么 |
|------|--------|
| `BGM/` | 背景音乐（循环播放的长音频） |
| `SFX/` | 音效（泡泡破裂、蓄力、UI 点击等短音频） |

## 数据 `Data/`

策划的配置表原始文件（Excel / CSV / JSON）放这里。

> 用 GameFramework 的 DataTable 模块时：**原始表格放这里**，由工具生成的 C# 数据行类放 `Scripts/Data/`。

## 代码 `Scripts/`

| 目录 | 放什么 | 举例 |
|------|--------|------|
| `Procedure/` | 游戏流程（生命周期状态机） | `ProcedureLaunch` `ProcedureMenu` `ProcedureMain` |
| `Gameplay/` | 核心玩法逻辑 | 泡泡生成、浮力计算、Boids 群体行为 |
| `UI/` | 界面逻辑（继承 `UIFormLogic`） | `MenuForm` `HudForm` |
| `Data/` | 数据结构与配置读取 | `DataRow` 子类、常量定义 |
| `Utility/` | 工具类、扩展方法 | 数学工具、对象池封装 |
| `Editor/` | 编辑器扩展（**仅编辑器**） | 一键配置、批量工具 |

### ⚠️ 关于 `Editor` 文件夹

**任何**叫 `Editor` 的文件夹（不管在第几层）里，脚本都**只在编辑器下编译**，不会被打进最终包。

- 编辑器专用代码（用到 `UnityEditor` 命名空间的）**必须**放 `Editor/` 里
- 反过来，放到 `Editor/` 里的代码**运行时用不了**，普通游戏逻辑别往里放

这是 Unity 的硬性规则，放错会导致打包失败。

### 命名空间约定

所有项目代码统一用 `PAO` 命名空间：

```csharp
namespace PAO
{
    public class BubbleSpawner : MonoBehaviour { }
}
```

子模块可以再分层，例如 `PAO.UI`、`PAO.Gameplay`，但**不要另起炉灶**。

## 命名规范

统一用**英文 + PascalCase**，不要用中文文件名（某些工具链会挂）：

| 类型 | 规范 | 例子 |
|------|------|------|
| 场景 | `PascalCase` | `Level01` `MainMenu` |
| 预制体 | `PascalCase` | `Bubble` `PlayerCharacter` |
| 脚本 | 类名与文件名**必须一致** | `BubbleSpawner.cs` → `class BubbleSpawner` |
| 贴图 | `T_` 前缀 | `T_Bubble_01` |
| 材质 | `M_` 前缀 | `M_Bubble_Transparent` |
| 模型 | `SM_` 前缀（静态网格） | `SM_Honeycomb_Block` |
| 音效 | `SFX_` 前缀 | `SFX_Bubble_Pop` |
| 音乐 | `BGM_` 前缀 | `BGM_MainTheme` |

> 同一个资源的不同变体用两位数字后缀：`T_Bubble_01`、`T_Bubble_02`。
> **不要**用 `T_Bubble_new`、`T_Bubble_final`、`T_Bubble_final2` —— 这是团队协作的头号杀手。

## 协作分工速查

| 你是 | 往哪放 |
|------|--------|
| 美术 | `Art/`（贴图 → `Textures/`，模型 → `Models/`）；UI 图 → `UI/Sprites/` |
| 策划 | 数值表 → `Data/` |
| 程序 | 代码 → `Scripts/`；预制体 → `Prefabs/`；场景 → `Scenes/` |
| 所有人 | **不要往 `Assets/` 根目录丢东西** |

## 提交前检查

1. `.meta` 文件**必须一起提交**（Unity 靠它维持资源引用，丢了引用就全断）
   - 已经在 `.gitignore` 里保护好了，正常 `git add` 即可
2. **不要提交** `Library/` `Temp/` `Logs/` `obj/` `Build/`（同样已被 `.gitignore` 挡掉）
3. 提交前对一下 `git status`，确认没混进奇怪的大文件
