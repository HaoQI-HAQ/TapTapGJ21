## 四个部分共用一个「水面亮网」

**这是整套效果的统一原理，理解了它四个部分就都懂了：**

水面被波浪折射，把阳光聚成一张**会动的亮网**。这张网有三个投影：

| 投影到哪 | 看到什么 | 对应代码 |
|---|---|---|
| 往下打到地板 | **焦散** —— 地板上游动的亮网 | `PAO_SampleCaustics` 用在 Pass 0 |
| 沿视线往下看 | **体积光** —— 一束束光柱 | 光柱亮度 = 水面命中点的焦散值 |
| 抬头看水面本身 | **波光粼粼** | `PAO_WaterSurfaceShade` 复用同一套细胞噪声 |

所以**它们天然自洽**：地板上的亮斑正好在光柱底下，抬头看到的亮纹和脚下的对应。
这不是巧合，是刻意共用同一张网的缘故。

> ⚠️ 上一版体积光是沿视线采样 3D 噪声做的，那是**体积雾**不是光柱 ——
> 噪声场里没有「一束」这个概念，每条光线穿过好几块噪声平均下来就平了。
> 现在的做法是「水面命中点定强度，沿射线保持不变」，那才是柱。
> 详见 `UnderwaterGodRays.shader` 顶部的说明。

## 调试模式：焦散看不见时先开这个

焦散看不见有**五种完全不同的原因，画面上表现却一模一样**（都是没有）：

| 模式 | 应该看到什么 | 不对说明什么 |
|---|---|---|
| `Caustics` | 一张会动的亮网 | 全黑 → 图案没算出来 |
| `SurfaceMatch` | 白色 = 这个像素还是几何表面 | 全黑 → 被透明物体盖住，或深度对不上 |
| `ViewDistance` | 随距离变亮的灰 | 不对 → 深度读错了 |
| `WorldGrid` | 规则格子 | 糊掉/条纹 → **世界坐标重建错了** |
| `GodRayBeam` | 水面上的亮网 | 全黑 → 水面命中点算错了 |

背景用**深灰而不是纯黑**：这样「没算出来」和「算出来是 0」能区分开 ——
纯黑底的话这两种情况长得一样，等于没调试。

开关在 URP Renderer 资产的 **Underwater Render Feature → 调试 → Debug Mode**。

## 一、它由什么组成

```
Underwater                      ← 场景里只放这一个（脚本：WaterVolume）
  ├─ WaterSurface               ← 水面网格 + WaterSurface 材质
  └─ UnderwaterTrigger          ← 一个 BoxCollider + Volume
                                   （相机进去 = 后处理生效，不需要写脚本）

Underwater Render Feature       ← 装在 URP Renderer 资产上，四段注入：
  ├─ Stage.Caustics             算焦散量 → 半分辨率中间纹理
  ├─ Stage.CausticsComposite    混回画面
  ├─ Stage.Composite            深度雾（全分辨率）
  └─ Stage.GodRays              体积光（半分辨率）
```

**和泡泡系统的关系**：两边完全独立，没有一行互相调用。但**注入顺序必须对**——
泡泡（`BubbleSDFRenderFeature`）和泡泡潮（`BubbleTideRenderFeature`）都在
`AfterRenderingTransparents`（= 500），水下雾在 **550**。

如果雾排在泡泡前面，泡泡就会是「泡在干净空气里」，而画面其他地方都是雾，
一眼穿帮。这是这种叠加式全屏效果最经典的失败模式。

### ⚠️ 一条不能破的规则：相机颜色只写不读

四段里有三段要「把画面改一改再写回去」。**每一步都必须先把画面拷进一张自己的
纹理，再从那张纹理读。**

```
✘ 错：读相机颜色 → 改 → 写相机颜色
✔ 对：拷相机颜色 → 自己的纹理 ──读──→ 改 → 写相机颜色
```

破掉这条规则会同时踩三个坑：

1. **UV 的 Y 翻转。** 渲染到 RT 和渲染到相机颜色，UV 的 Y 方向是相反的
   （Unity 的 RT 约定），由 `GetFullScreenTriangleTexCoord` 通过
   `_ProjectionParams.x` 自动补偿。「从纹理读 + 写相机颜色」天然成立；
   「从相机颜色读 + 写相机颜色」不成立——同一套 uv 拿去采样会上下颠倒，
   焦散会跑到天花板上去。
2. **同一张 RT 既读又写**，在部分平台上是未定义行为。编辑器里九成时候看着是对的，
   剩下那一成在打包后表现为画面偶尔整块花掉，且只在特定分辨率复现。
3. **`Blitter.BlitCameraTexture` 会直接抛异常。** 实测过：

   ```
   Assertion failed
   UnityEngine.Rendering.Blitter:BlitCameraTexture(...)
   ArgumentNullException: Value cannot be null. Parameter name: value
   ```

   每帧刷几百条。项目里泡泡 SDF / 泡泡潮那两套能用 `Blitter`，是因为它们
   **只把相机颜色当源**，输出永远写进自己的中间纹理。别看到它们能用就跟着用。

4. **源和目标的尺寸必须一致。** `Blitter` 的 viewport 是按源的 `rtHandleScale`
   算的，全分辨率的源 + 半分辨率的目标 = 只画到四分之一块区域。
   所以每一段的 `Configure` 都按自己的除数分配纹理。

代价是每帧多几次全屏拷贝。拷一次是「一次采样 + 一次写入」，比一趟带循环的
Pass 便宜得多——换来的是不会莫名其妙炸。

## 二、参数分两处，各管一摊

> **改哪个地方生效是确定的，不用猜。** 这是刻意设计的，见下面每条的说明。

### 1. 观感 → 场景里的 `WaterVolume`

水面高度、水色、雾浓度、焦散强度、光柱方向、步数……全在这里。

它是**唯一的数据源**：`PushGlobals()` 每帧把所有参数推成全局 shader 变量，
水面材质和两个全屏 shader 都从同一份读。

**唯一的例外是水面波光**：它的频率 / 亮度 / 亮边走**水面材质自己的属性**
（`WaterSurface.mat`），不走全局变量——因为只有那一块网格用它们。
搭的时候会从 `WaterVolume` 烤一份初值进材质，之后想调请直接改材质。

想让水更「弱」一点，调 `underwaterStrength`（总体强度，0~1）。这是总旋钮。

### 2. 注入时机 + 分辨率 → URP Renderer 资产上的 **Underwater Render Feature**

只有这几项是渲染管线相关的：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `causticsEvent` / `causticsCompositeEvent` | `BeforeRenderingSkybox`（350） | **改成 500 会让焦散穿透泡泡和玻璃** |
| `godRayEvent` | `AfterRenderingTransparents + 30`（530） | 排在雾之前，光柱被雾淡化一点——光在浑水里本来就该衰减 |
| `compositeEvent` | `AfterRenderingTransparents + 50`（550） | 必须排在泡泡（500）之后，否则泡泡「泡在干净空气里」 |
| `causticsResolutionDivisor` | 2 | 半分辨率。焦散花纹是低频的，看不出来 |
| `godRayResolutionDivisor` | 2 | **别改成 1**，算力翻倍而观感几乎无差别 |
| `causticsEnabled` / `fogEnabled` / `godRaysEnabled` | 全开 | 三段总开关 |

⚠️ 在这里关掉某一段之后，`WaterVolume` 上对应的参数就完全失效了。

#### ⚠️ 注入时机的硬上限：590

URP 的 `RenderPassEvent` 实际数值（从 `ScriptableRenderPass.cs` 读出来的）：

```
AfterRenderingOpaques         = 300
BeforeRenderingSkybox         = 350
BeforeRenderingTransparents   = 450
AfterRenderingTransparents    = 500
AfterRenderingPostProcessing  = 600   ← 硬边界
```

**超过 590 之后，相机颜色目标已经交还给渲染管线，`cameraColorTargetHandle`
开始返回 null，那一段就静默地画不出来了。**

这个坑踩过一次：体积光原来设在 560，看着离 600 还有 40 的余量，
实际已经踩线，Console 报「拿不到相机颜色目标（相机类型 Game）」。

现在由 `UnderwaterSettings.ClampEvent()` 强制夹住——配错也不会静默失效，
而是会在 Console 里明说「被夹到上限了」。**但夹到上限仍然是不对的位置**，
所以真要改的话，请留在 350 ~ 590 之间。

## 三、水面高度：唯一一个必须人工确认的值

一键搭建按「房间包围盒顶部的 85%，且高出地板 6 米」估一个初值。
**但它一定是估的，必须自己核对。**

填错的后果很特别：**不会报任何错**。焦散、雾、光柱全部按错误的高度算，
画面只是「怪」，看起来像参数没调好，而不是像配置错了。

核对办法：选中 `Underwater`，Scene 视图里会画出

- 一个**亮蓝线框** = 水面（就是这个平面，抬头应该正好能看到它在头顶几米）
- 一个**暗蓝线框** = 水下过渡带（相机穿过这一段时效果平滑进出）
- 一条**黄线** = 光柱方向

## 四、贴图：现在一张都不需要

焦散、波光、光柱噪波**全部是 shader 里程序化算的**：0 张贴图、0 字节显存、
0 次采样，代价是每像素几十条 ALU。

这么选有两个实在的理由：

- **平铺重复**：玩家一抬头就是整片水面。用 256×256 的贴图平铺几十次，
  重复的花纹肉眼可辨——而水下恰恰是个「一直在看远处」的场景。
- **分辨率错配**：焦散要铺满地板，按 1 米一格算就是 60×60 米 = 3600 格，
  想不糊就得 4096² 贴图，16 MB 显存换一个能算出来的东西。

### ★ 焦散贴图插槽（已做好，放进去就生效）

**不需要改代码。** 选中场景里的 `Underwater`，把图拖到 **`causticsTexture`** 上即可。

- **留空** → 走 shader 里程序化生成的细胞噪声
- **放图** → 自动切换成「两层滚动 + 呼吸调制」的贴图版本

运行时切换也生效，随时可以对比两种效果。

#### 这张图的要求

| 项 | 值 | 不满足会怎样 |
|---|---|---|
| **无缝平铺** | **必须**。这是唯一的硬要求 | 满地板明显的方格接缝 |
| 尺寸 | 512×512 就够 | 大了纯浪费显存（它会在世界里反复平铺） |
| 边长 | 2 的幂（512/1024） | 某些平台被强制缩放、变糊 |
| 内容 | 灰度。亮 = 光斑，暗 = 阴影 | — |
| Wrap Mode | `Repeat` | 同「无缝」那条 |
| sRGB | 关掉 | 影响很小，可以先不管 |
| Read/Write | 关掉 | 白占一份内存副本 |

「检查安装状态」会把上面每一条都验一遍——**这些设置错了都不会报错，只会画面怪**，所以专门做了一轮检查。

#### 为什么这张图确实需要美术（而别的几张不需要）

程序化的细胞噪声天生无缝、永远能跑，但它画不出**有粗有细、有疏有密的网状**——
那需要人的判断。参考图里地板上的光斑就是这种不均匀的网。
这是整套效果里唯一一张「美术做得比程序化好」的贴图。

#### 另外三处纹理相关的判断

| 用途 | 结论 | 理由 |
|---|---|---|
| 水面涟漪 | ⚠️ 先不做 | 只在水面成为画面重点时才值得。现在三层程序化噪声够用 |
| 粒子贴图（浮尘） | ❌ 别做 | 就是一张软圆点。美术画和程序化生成**没有任何区别**，不值得占用美术时间 |
| 3D 噪声（光柱降噪） | ❌ 别做 | 收益只是性能，观感零提升。而且 3D 纹理在 Unity 里容易出错 |

要接水面涟漪的话，改 `PAO_WaterSurfaceShade()` 里涟漪那一段，
把三层 `PAO_ValueNoise2` 换成两层滚动采样 + 一层扭曲——和焦散那套同构。

### 贴图放哪个目录

```
Assets/GameMain/Art/Textures/水下/     ← 新建这个目录放水下相关的图
```

命名建议 `Caustics_01.png` 这种带序号的形式，方便以后出第二版直接并排对比。
（目录规范和现有资源一致：`Art/Textures/<题材>/`，参考现有的 `水母罐子/`、`水母耳机/`。）

## 五、性能

默认参数下（PC，1080p，半分辨率焦散 + 半分辨率体积光）：

| 段 | 分辨率 | 说明 |
|---|---|---|
| 焦散 ×2 趟 | 1/2 | 便宜，约等于一次全屏采样 + 一次加法 |
| 深度雾 | 全分辨率 | **很便宜**：一次深度采样 + 一个 lerp。全分辨率没关系 |
| 体积光 | 1/2 | **最贵的一项**。14 步 × 每步一个 3D FBM |
| 水面 | 全分辨率 | 三层 2D 噪声 + 焦散图案。一块网格 |

### 要压帧率，按这个顺序调

1. **`WaterVolume.godRaySteps`：14 → 8**。这是性价比最高的一刀。
   低于 6 会开始出现层状 banding。
2. **`WaterVolume.godRayDistance`：45 → 25**。水本来就浑，走再远也看不见。
3. **`UnderwaterRenderFeature.godRayResolutionDivisor`：2 → 3**。
4. 最后才考虑关掉体积光。关了画面会立刻变得「干」。

**不要为了性能把雾关掉**——它是「在水里」这个感觉的主要来源，而且它很便宜。

### 为什么体积光是独立的一趟、跑在半分辨率上

雾是「一次深度采样 + 一个 lerp」，全分辨率几乎免费。
体积光是「14 步循环 × 每步 8 次哈希」，全分辨率下比其余全部加起来还贵。

而它恰好**最不需要全分辨率**：光柱是十几米厚的体积，边缘本来就晕开，
半分辨率下靠 Blitter 的双线性上采样补回来，肉眼分辨不出。

拆开之后省掉正好一半的步进算力，观感损失约等于零。

## 六、几个必须知道的坑

### 1. 深度纹理必须开着

三个 URP 资产的 `m_RequireDepthTexture` 现在都是 **1**，是对的。

> ⚠️ `BubbleTide/README.md` 里写的「三个 URP 资产的 m_RequireDepthTexture 都是 0」
> **已经过期了**。写那份文档时确实是 0，后来改了。

关掉它**不会报任何错**，只是焦散整体消失（体积光还在，因为它的射线方向是从
相机矩阵现算的）。这是最难查的一种失败。状态检查工具会单独把这一项列出来。

### 2. 注入顺序错了会让泡泡「泡在干净空气里」

见第一节。雾必须排在 500 之后。`BubbleSDFRenderFeature` 和
`BubbleTideRenderFeature` 都改了 `passEvent` 的话要一起看。

### 3. 焦散为什么要把结果存进纹理再读回来

焦散必须**长在几何体上**（参考图里地面的光斑是长在地板上的，不是浮在画面
最上层的一层膜），所以它得在透明物体**之前**跑。

雾和体积光反过来，必须罩在**所有东西之上**（包括泡泡），否则泡泡是干净的。

中间隔着整个透明渲染阶段，共享不了寄存器，只能走纹理。
于是多了一趟「把焦散混回画面」——它只做一次采样和一次加法，成本约等于零。

那张中间纹理的 **G 通道存了当时那一趟看到的视距**，用来让最后那趟能判断
「这个像素还是原来那个不透明表面吗」。不存的话焦散会**穿透**近处的泡泡，
泡泡身上会浮着地板的亮纹。

### 4. 不要试图「读相机颜色又写相机颜色」

有三趟的输出目标是相机颜色本身（焦散合成、体积光）。每一趟都先拷一份画面
到 `_PAO_SourceTexture` 再读那一份。

不要为了省这次拷贝改成「一趟读相机颜色写相机颜色」——在编辑器里它九成时候
是对的，剩下那一成会在打包后出现，表现是画面偶尔整块花掉，而且只在特定
分辨率下复现。

### 5. 水面是平面，不是半球穹顶

半球穹顶适合「一望无际的大海」，但房间是有墙的：
半径 200、水面在 y=10 的穹顶，往外 100 米处已经降到 y=-11.6，
早就在地板下面了，玩家会看到水面**穿进地板**。

一块大平面从下方看永远是一条水平线，正是参考图里那种效果。
尺寸开到比房间大 3 倍以上，玩家看不到边。

### 6. 水面用的是 `Cull Front`

玩家永远在水下、永远从**下方**看这块面。`Cull Front` = 从下面看得到、
从上面看不到。这样万一相机跑到水面以上，也不会看到一块奇怪的发光地板。

队列是 `Geometry` 而不是 `Transparent`——它是个实心面，需要正常写深度，
才能把水下的泡泡、地形正确挡住。

### 7. `_PAO_` 前缀不能去掉

这些都是**全局** shader 变量，会和 URP 自己的、以及将来接入的任何插件抢名字。
URP 内部已经占用了大量 `_Camera` / `_ZBuffer` / `_Blit` 开头的名字，
撞上就是「莫名其妙渲染错」，而且极难定位。

名字统一定义在 `Scripts/Gameplay/Underwater/UnderwaterShaderIDs.cs`，
shader 侧的声明在 `UnderwaterInclude.hlsl` 顶部。**改名字必须两边一起改。**

## 八、下一步可以做的

1. **浮尘粒子。** 水里飘的小颗粒，是「有体积」最便宜的补强。
   一个 Particle System，Soft 圆点贴图，世界空间的低速漂移，成本几乎为零。
2. **音效。** 水下的低频闷响 + 偶尔的气泡声。参考图那种氛围里，
   声音可能比画面更重要。
3. **焦散打在角色身上。** 现在焦散只作用于不透明几何体（角色是不透明的，
   所以其实已经打上了）。但如果角色用了自定义 shader，需要它参与深度写入。
4. **水面折射。** 现在水下看水面是「假」的波光，看不到水面上方的东西。
   要做真的需要一次反射/折射相机 —— 对卡通画风来说性价比不高。
5. **真体积光。** 现在这套已经是真的沿视线步进了（不是屏幕空间径向模糊），
   但光源遮罩用的是程序化噪声，不是真实的水面焦散。想要更「物理」的话，
   可以把 `PAO_ShaftPattern` 换成「往太阳方向投到水面、采样焦散图案」。
