# 机关交互使用说明：拉杆 / 门 / 门边镜头

> 目标效果：玩家靠近拉杆 → 出现白底方格 `E` → 按 E → 拉杆转到设定角度 → 门在设定延迟后旋转 / 平移 → 画面切到门边镜头 → 镜头结束自动回到玩家。

这套功能全部在 `UnityProject/PAO/Assets/GameMain/Scripts` 下，不依赖任何预制体，也不需要在场景里预先摆 Canvas。

---

## 0. 30 秒试玩

1. 用 Unity Hub 打开 `UnityProject/PAO`（Unity 2022.3.34f1）。
2. 等编译完成，点菜单：

   **PAO → 关卡 → 机关 → 打开或生成演示场景**

3. 打开后直接按 **Play**。
4. 用 **WASD** 走到橙色拉杆旁，看到白底 `E` 后按 **E**。

演示场景会自动生成在：

```
Assets/GameMain/Scenes/MechanismDemo.unity
```

场景里已经放好：玩家、拉杆、门、门边镜头。拉杆转完后门等 0.5 秒开始开，同时切到门边镜头，3.5 秒后切回玩家。

> 演示场景是编辑器工具生成的占位场景，不是最终美术。它的作用是让你先确认整套流程，再把自己的模型换进去。

## 1. 文件在哪

| 文件 | 作用 |
|------|------|
| `Scripts/Gameplay/Mechanism/LeverInteractable.cs` | 拉杆：距离检测、E 提示、旋转、联动门 |
| `Scripts/Gameplay/Mechanism/MechanismDoor.cs` | 门：延迟、旋转 / 平移、开关事件 |
| `Scripts/Gameplay/Mechanism/MechanismCameraShot.cs` | 门边镜头：切镜头、锁玩家、自动切回 |
| `Scripts/Gameplay/Mechanism/InteractionPrompt.cs` | 白底 `E` 提示 UI，运行时自动生成 |
| `Scripts/Editor/MechanismSetupTools.cs` | 菜单工具 + 演示场景生成器 |
| `Scripts/Gameplay/PlayerController.cs` | 新增了 `ControlLocked` 属性，供镜头演出锁玩家 |

组件在 Inspector 里的位置：

- **Add Component → PAO → 关卡 → 拉杆交互（Lever Interactable）**
- **Add Component → PAO → 关卡 → 机关门（Mechanism Door）**
- **Add Component → PAO → 关卡 → 门边镜头（Mechanism Camera Shot）**

## 2. 把自己的拉杆模型接进来

### 2.1 推荐层级

```text
Lever                         ← 挂 Lever Interactable
├── Base                      ← 固定底座，不转
├── Hinge                     ← 空物体，放在齿轮 / 转轴的正中心
│   └── Handle                ← 会转的手柄模型
└── PromptAnchor              ← 空物体，决定 E 提示悬在什么位置
```

`Handle` 不一定要挂在 `Hinge` 下面。脚本是“绕 Hinge 的位置转”，所以只要把 **Rotating Part** 和 **Hinge** 两个引用赋对，手柄放在哪一层都能转。推荐挂在 Hinge 下，方便在 Scene 里直接看。

### 2.2 操作步骤

1. 把拉杆模型拖进场景。底座留在原地。
2. 在齿轮中心新建一个空物体，命名 `Hinge`。
3. 把会动的手柄拖到 `Hinge` 下面。如果不想改层级，也可以不改，后面直接赋引用。
4. 在拉杆上方新建一个空物体，命名 `PromptAnchor`，放在手柄顶端附近。
5. 在拉杆根物体上挂 **Lever Interactable**。
6. 在 Inspector 里填：

   | 字段 | 说明 |
   |------|------|
   | `Interact Distance` | 玩家离多近出现提示。默认 2.8 米 |
   | `Prompt Anchor` | 拖 `PromptAnchor`。留空则用根物体 + `Prompt Offset` |
   | `Prompt Label` | 方格下方的小字，可留空。例如“拉下拉杆” |
   | `Toggle Back` | 勾上后可以再按 E 推回去；不勾就是一次性 |
   | `Rotating Part` | 拖 `Handle` |
   | `Hinge` | 拖 `Hinge` 空物体 |
   | `Axis` | 转轴方向。拉杆在 XY 平面摆动一般填 `(0, 0, 1)` |
   | `Angle` | 拉到底转多少度。正负决定往哪边 |
   | `Duration` | 转动用时，默认 0.35 秒 |
   | `Ease` | 默认曲线即可 |
   | `Start Pulled` | 一开始就是拉到底的状态 |
   | `Target Door` | 拖要联动的那扇门 |

7. 点中拉杆，在 Scene 视图里看青色轴线。轴线就是转轴，白框是提示位置，绿色线框球是交互距离。
8. 试运行。如果手柄往反方向转，把 `Angle` 改成正 / 负；如果转的圆心不对，检查 `Hinge` 是不是在齿轮中心。

### 2.3 角度与轴

- `Axis` 是 **Hinge 的本地坐标轴**，不是世界轴。
- 模型在 XY 平面里像钟摆一样摆：`Axis = (0, 0, 1)`。
- 门 / 栏杆在水平面里扫：`Axis = (0, 1, 0)`。
- 不确定时先填 `(0, 0, 1)`，改 `Angle = 30` 试一下，看手柄绕哪根轴转。

### 2.4 一次性还是可推回

- `Toggle Back = false`：拉到底后不再出现提示。适合“开门后不再关”的关卡。
- `Toggle Back = true`：到底后再按 E 会推回原位。推回时会调用 `Target Door.Close()`。

> 模型如果自带 Animator 或非 Kinematic 的 Rigidbody，请先关掉动画 / 把刚体设为 Kinematic。本脚本是用 Transform 驱动旋转的，物理和动画同时改同一个物体会打架。

## 3. 把门接进来

### 3.1 推荐层级

```text
Door                          ← 挂 Mechanism Door
├── Frame                     ← 门框，不动
└── Hinge                     ← 空物体，放在合页位置
    └── Leaf                  ← 门板，挂碰撞体
```

普通单开门：`Hinge` 放在门板左侧边缘，`Leaf` 的本地 X 偏移约等于门宽的一半。

### 3.2 组件参数

| 字段 | 说明 |
|------|------|
| `Moving Part` | 拖门板 `Leaf`。留空则动门自己 |
| `Hinge` | 旋转中心。留空则绕门板自己的原点转 |
| `Motion` | `Rotate` 旋转 / `Slide` 平移 / `Rotate And Slide` 两者叠加 |
| `Rotate Axis` | 旋转轴，普通门填 `(0, 1, 0)` |
| `Open Angle` | 开门角度。正负决定往哪边开 |
| `Slide Offset` | 平移位移，按门板**父级**的坐标轴算 |
| `Delay` | 收到指令后等多久才开始动。默认 0.5 秒 |
| `Duration` | 从关到开用时。默认 1.2 秒 |
| `Ease` | 默认两头慢中间快；要机械感可以改成线性 |
| `Start Open` | 一开始就是开着的 |
| `Open Camera Shot` | 开门时启动的门边镜头，可留空 |
| `On Opened` 等 | UnityEvent，可接音效、粒子、对话 |

- 如果门板上有 `Rigidbody`，脚本会在 `Awake` 里把它设为 `Is Kinematic`，因为门是用 Transform 摆的。
- 门板上的碰撞体要放在 `Leaf` 上，跟着门一起动。门框的碰撞体留在 `Frame`。
- `Slide Offset` 例子：门沿父级 Z 轴推出 1.5 米，填 `(0, 0, 1.5)`。

### 3.3 对外方法

任何按钮、Timeline、对话脚本都可以直接调：

```csharp
door.Open();              // 开门，等 Delay 后开始
door.Close();             // 关门
door.Toggle();            // 开/关切换
door.SetOpenInstant(true); // 直接摆到开，不播动画、不切镜头
```

`MechanismDoor` 还提供 `IsOpen`、`IsFullyOpen`、`IsMoving`、`Progress` 给别的逻辑查询。

## 4. 门边镜头

### 4.1 为什么用第二台摄像机

`PlayerController` 每帧都会接管主摄像机的跟随、防穿墙、旋转。如果直接把主摄像机搬到门边，会和它打架，切回来还要还原位置。

这里改用第二台摄像机：

1. 门边摄像机平时禁用；
2. 开门时启用，`Depth` 比主摄像机高 20，画面盖在主摄像机上面；
3. 显示期间把 `PlayerController.ControlLocked` 设为 true，玩家不会走开；
4. 时间到自动禁用，主摄像机一直在原位，切回来没有跳变。

### 4.2 摆法

1. 在门旁边新建一台 **Camera**，摆好构图。
2. 把 Camera 组件的 **Enabled** 勾掉（或者把物体隐藏）。
3. **Tag 保持 Untagged**，不要设成 `MainCamera`。
4. 在任意空物体上挂 **Mechanism Camera Shot**。
5. 填：

   | 字段 | 说明 |
   |------|------|
   | `Shot Camera` | 拖门边那台相机 |
   | `Shot Point` | 可选。播放时把相机搬到这个位置和朝向 |
   | `Look At` | 可选。播放时强制看向这个目标 |
   | `Duration` | 停留多久。默认 3.5 秒；填 0 = 不自动切回 |
   | `Return To Gameplay` | 时间到自动切回；关掉则一直停住，等 `StopShot()` |
   | `Lock Player Control` | 显示期间锁住玩家移动和视角 |
   | `Depth Boost` | 比主摄像机高多少，默认 20 |

6. 把这台 `Mechanism Camera Shot` 拖到门的 `Open Camera Shot` 字段。

### 4.3 触发与结束

- 门调用 `Open()` 时会立刻 `Play()` 镜头，然后才开始算门的 `Delay`。所以玩家会先看到门边的画面，等 0.5 秒后门开始动。
- `Duration` 到了自动 `StopShot()`。
- 也可以从任何脚本手动 `Play()` / `StopShot()`。
- 想“镜头一直停在门边”，把 `Return To Gameplay` 关掉，或者把 `Duration` 填 0，之后手动 `StopShot()`。

### 4.4 快捷创建

选中一扇挂着 `Mechanism Door` 的门，点菜单：

**PAO → 关卡 → 机关 → 为选中的门创建门边镜头**

会自动在门正面偏一侧生成相机、Look Target 和镜头控制器，并自动接到这扇门上。生成后自己微调相机位置即可。

> 门边相机不要加 `AudioListener`。如果加了，脚本会在播放期间临时禁用它，避免两个 Listener 刷警告；但最干净的做法是干脆不加。

## 5. 联动方式

### 方式 A：直接拖引用（推荐）

把门拖到拉杆的 `Target Door`。拉到底时自动 `Open()`；勾了 `Toggle Back` 时，推回去自动 `Close()`。

### 方式 B：UnityEvent

不用 `Target Door`，在拉杆的 `On Pulled` 里点 `+`，把门拖进去，选 `MechanismDoor.Open`。这样可以在开门前插入音效、对白、镜头等。

### 方式 C：代码调用

```csharp
public LeverInteractable lever;
public MechanismDoor door;

void Start()
{
    // 也可以完全不用拉杆，自己做一个按钮：
    // 按 E 时直接 door.Open();
}
```

### 时序

```text
按 E
  └─ 拉杆旋转 0.35s
       └─ 门 Open()
            ├─ 门边镜头立刻开始（3.5s）
            └─ 等 0.5s
                 └─ 门旋转 1.2s
                      └─ On Opened
```

所有时间都可以在 Inspector 里改。延迟和动画都用 `Time.deltaTime`，暂停菜单把 `timeScale` 设为 0 时会一起停。

## 6. 提示 UI 说明

- 不需要在场景里放 Canvas。第一次调用时自动生成一个 `[Interaction Prompt]` 物体，场景切换时销毁。
- 白底圆角方格 + 按键字母。默认显示项目统一交互键（默认 `E`；如果玩家改键，会显示新键；手柄会显示对应按钮）。
- 多个拉杆同时在附近时，只显示离摄像机最近的那个。
- 提示会跟着世界坐标走，超出屏幕、被镜头切走、暂停、打开菜单时自动隐藏。
- `Prompt Label` 可以写中文，例如“拉下拉杆”。优先使用 `Resources/PAOUIConfig` 里配置的项目中文字体，打包后不会掉字；没有配置时才找系统字体，最后退回内置字体（只影响这行小字，不影响 `E`）。

## 7. 常见问题

| 现象 | 检查 |
|------|------|
| 靠近没有 `E` | 场景里有没有 `PlayerController`；距离够不够；`Time.timeScale` 是否为 0；是不是刚播过门边镜头；一次性拉杆是不是已经拉过 |
| 按 E 没反应 | 交互键是否被改过（项目统一绑定，默认 E）；`UIInput.Blocked` 是否为 true；拉杆是否正在转；玩家是不是在泡泡里 |
| 拉杆转了，但门没开 | `Target Door` 有没有拖；或者 `On Pulled` 有没有接；门的 `Delay` / `Duration` 是否正常 |
| 拉杆绕错圆心 | `Hinge` 是否在齿轮中心；`Rotating Part` 是否拖的是手柄而不是整个拉杆 |
| 拉杆方向反了 | 把 `Angle` 改成正 / 负；或者把 `Axis` 反向 |
| 门开的方向不对 | `Open Angle` 正负；`Rotate Axis` 方向；`Hinge` 是否在合页上 |
| 门平移方向不对 | `Slide Offset` 是按门板父级坐标轴算的，改分量符号或换轴 |
| 门从门框里穿过去 | 检查 `Hinge` 是否在门轴边缘，`Leaf` 的原点是否在门板中心；脚本是按圆弧走的，不会用直线插值 |
| 镜头没切过去 | 门边相机是不是被设成了 `MainCamera`；是不是和主摄像机同一台；URP 下相机是不是 `Overlay`（必须是 Base）；`Open Camera Shot` 有没有拖 |
| 镜头切过去但玩家还能走 | `Lock Player Control` 是否勾上；场景里有没有 `PlayerController` |
| 镜头不切回来 | `Return To Gameplay` 是否勾上；`Duration` 是否大于 0；是不是手动调过 `StopShot` |
| 两个 AudioListener 警告 | 门边相机不要加 AudioListener；脚本也会临时禁用，但最好别加 |
| 暂停时门/拉杆还在动 | 检查是否有别的脚本用 `unscaledDeltaTime` 驱动它们；本套脚本用的是 scaled time |

## 8. 实现备注（给写代码的队友）

- `LeverInteractable` 在世界空间绕 `Hinge.position` 旋转，手柄不需要是 Hinge 的子物体也能正确转。
- 旋转开始时记录手柄的初始世界位置 / 朝向；运行时如果整个拉杆被父物体移动，不会自动重新记录（关卡机关一般是静态的）。
- `MechanismDoor` 的旋转用“角度 → 圆弧位置”逐帧计算，而不是关门位置到开门位置的直线 `Lerp`，否则门板会切进门框。
- `MechanismCameraShot` 使用静态计数 `IsAnyPlaying`，拉杆和提示 UI 会在这期间静默；演出结束自动恢复。
- `InteractionPrompt` 的 Canvas 排序为 1500，高于游戏 HUD（1000），低于过场（3000）；暂停 / 菜单打开时会自动隐藏。
- `PlayerController.ControlLocked` 只停移动和视角，不碰 `Time.timeScale`、不碰其他机关；光标保持原状。

## 9. 目前的限制

- 门边镜头不会自动隐藏游戏 HUD，也不会接管暂停菜单。需要的话可以在 `On Started` / `On Finished` 里接自己的显隐逻辑。
- 拉杆 / 门都假设是静态关卡物件。如果整个机关会被父物体带着移动，需要在移动后重新调用初始化或扩展脚本。
- 提示 UI 的中文小字优先使用 `PAOUIConfig` 的中文字体；`E` 本身用 Unity 内置字体，不受影响。
- 演示场景是占位几何体，只用于验证流程，不是正式美术资源。
