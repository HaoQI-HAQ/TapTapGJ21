## 一、我重新理解的「泡泡潮」

先把之前的偏差摆正。我前几轮一直在按「潮水是主角」推进，但从你的截图和反馈看，
**你要的主角是泡泡本身，潮水只是它出现的节拍器。**

### 它应该是什么

| 维度 | 正确的理解 | 我之前跑偏的地方 |
|---|---|---|
| **主角** | 一颗颗**能看清的卡通泡泡**，它们自己就是画面 | 我把它当成"潮水的可视化" |
| **数量** | 几十颗（你要 <100），每颗 5~10 米，**看得见个体** | 我按 190~260 颗铺，个体感全没了 |
| **排序** | 空间上是**半随机散布**，不是排队 | 我写成了规则网格，这是硬 bug |
| **节拍** | 从少数几个入口开始，**一朵一朵涌出来**，最后淹没全场 | 现在没有明显的"从哪开始" |
| **角色** | **压迫感 + 氛围**，不是血条 | 我一直想把它变成玩法计时器 |
| **旧渲染** | 原来的体积潮水是**上一版的实现**，这一版要取代它 | 我以为两者要并存 |

一句话：**它是一场缓慢的、有形状的"涨潮"，涨潮的物质是一颗颗巨大的卡通泡泡。**
重点在"一颗颗"和"涨"这两件事上。

### 由此推出的设计约束

1. **必须看得见单颗** → 泡泡不能互相穿插太多，要有缝（`Spacing Multiplier` 那个参数就是为这个加的）
2. **必须不整齐** → 位置要抖动、大小要差异，否则一眼假
3. **必须有方向** → 玩家要能感觉到「它从那边过来了」，而不是"到处同时出现"
4. **必须不挡视线** → 泡泡是氛围，挡死了就没法玩了

## 二、问题 1：位置太规整（最容易修，也最影响观感）

**这是我的硬 bug，不是调参问题。** 看 `BubbleTideInstanceRenderer.BuildLayout`：

```csharp
// 块中心的世界坐标
Vector3 center = new Vector3(
    bounds.min.x + (bx + 0.5f) * blockSize.x,
    bounds.min.y + (by + 0.5f) * blockSize.y + m_HeightOffset,
    bounds.min.z + (bz + 0.5f) * blockSize.z);
```

**纯规则网格，零随机。** 三个 for 循环扫过去，每块正中心放一颗 ——
所以截图里就是"排队"。位置、大小全都一模一样，一眼就是程序生成的。

### 修法（三层，从便宜到讲究）

**① 位置抖动（必须做）**
每颗泡泡在它那块里随机偏移，但**偏移量不能超过"块的一半减去半径"**，
否则会跑到隔壁块去、或者造成忽疏忽密。加一个 `Jitter` 参数，0~0.5（占可偏移空间的比例）。

```
可偏移空间 = 块半边 - 半径         // 保证不越界、不互相插
pos = 块中心 + 哈希随机(-1..1) * 可偏移空间 * jitter
```

用现有那套确定性哈希（`Hash01`），保证每次跑出来一样 ——
调试时"改了参数"和"换了个种子"不会混在一起。

**② 尺寸差异（必须做）**
现在所有泡泡半径完全相同。给每颗乘一个 0.75~1.25 的哈希系数。
大球小球混着才有"一堆泡泡"的层次，这是泡泡材质本身都在做的事
（你原来的 `BubbleSDF` 里 `radius = Lerp(基础*0.6, 基础*1.25, hash)` 就是这个思路）。

**③ 打破网格本身（可选，效果最好）**
抖动解决"排得整齐"，但解决不了"格子的痕迹"。
更彻底的做法是**不用块中心，用一封装的蓝噪声点**：
在包围盒里撒比目标数多 3 倍的候选点，做一遍 Poisson-disk 剔除，
留下的就是天然均匀、又完全没有网格痕迹的分布。

对 100 颗泡泡来说这一步只要几毫秒，**性价比很高**。
而且它天然解决了"泡泡之间要有缝"这件事 —— 间距由最小距离参数直接控制，
比现在的"块大小反推半径"直观得多。

**我建议直接上 ③**，因为它同时修掉「规整」和「疏密」两个问题，
而且比现在这套（块 → 半径 → 间隙）的代码更短。

## 三、问题 2：启动卡约 10 秒

### 卡在哪

启动时的重活全在 `BubbleTideDirector.Bake()` 里，而且是**同步、单帧**跑完的：

| 步骤 | 成本 | 量级 |
|---|---|---|
| `MarkSolidCells` | **对每个体素格做一次 `Physics.CheckSphere`** | 格数 × 一次物理查询 |
| `BuildBubbleField` | 每颗球对周围 5³ 格写势场 | 球数 × 125 |
| `RunMultiSourceDijkstra` | 每个可达格 × 18 邻接 | 格数 × 18 |

**格数 = (包围盒体积 / 格距³)**。你 Inspector 里 `m_CellSize = 0.5`，
包围盒约 41.5 × 13 × 33.5 米 → **约 470 万格**。

那 `Physics.CheckSphere` 要做 **470 万次**。就算每次 1 微秒，也是接近 5 秒，
实际上带 broadphase 的查询远不止 1 微秒 —— **10 秒完全对得上**。

### 三个层面的修法

**① 立刻见效：把格距从 0.5 调到 1.0**
格数是**立方**关系：0.5 → 1.0 直接降到 **1/8**（470 万 → 59 万）。
烤制时间大概从 10 秒掉到 1 秒出头。

代价是潮水边缘变方一点 —— 但既然这一版的主角是泡泡，
**潮水表只用来查"第几秒淹到"，边缘精度根本不重要**。这是最划算的一刀。

**② 治本：把障碍层收窄**
`m_ObstacleMask` 现在是 `~0`（所有层）。`CheckSphere` 每帧要跟所有层求交，
把它改成只勾「地面/墙」那几层，查询会快很多。

**③ 体验层面：分帧烤 + 加载界面**
`Bake()` 现在一口气跑完。改成协程分帧（比如每帧最多 30 毫秒），
配合一个进度条。这是**10 秒问题唯一真正的"不卡"解法** ——
① 和 ② 是让它变快，③ 是让它不阻塞。

**④ 顺手可做：缓存**
障碍物是静态的话，体素化结果（哪些格是实心）可以缓存成一个文件或 ScriptableObject，
第二次进 Play 直接读，跳过 470 万次物理查询。对迭代速度帮助极大。

> **建议**：先做 ①（一分钟的事，立刻看到差别），再做 ④（缓存，调试爽），
> 最后做 ③（真要发布时再用）。② 顺手就改。

## 四、问题 3：还是一坨黑的在旋转

这个我**不敢再猜了** —— 上一轮我按"相机在泡泡内部"解释，修了描边和薄膜，
但现在看截图，黑块的光照是有结构的（有明显的高光/暗部渐变），
说明它**在正常走卡通着色，只是颜色算出来接近黑**。

### 我怀疑的几个点（按可能性排序）

1. **主光方向/颜色**：`GetMainLight()` 拿到的是场景主方向光。如果这个场景的
   主光是背光、或者强度很低，那 `specBand * _SpecIntensity * mainLight.color` 直接归零，
   而泡泡的颜色几乎全靠高光 + 彩虹 + 环境色撑，没有漫反射项。
   **泡泡材质本身就没有「底色 × 光照」这一项**，所以一旦主光和环境都暗，它就是黑的。

2. **`_EnvColor` / `_EnvIntensity` 没生效**：环境那一项是
   `lerp(_EnvColor, white, envBand*0.35) * _EnvIntensity * 0.45`，
   如果材质是新生成的、参数取到默认值 `_EnvIntensity = 0.55`，应该有一点亮度。

3. **彩虹项 `_Iridescence`**：默认 1.0，`iridBand = XStep(saturate(1-NoV))` ——
   正对相机时接近 0，所以正面本来就没彩虹，只有边缘有。

4. **两个 Pass 都在画**：`TideOutline` 和 `TideBody` 都是 `UniversalForward`，
   描边先画、`ZWrite On`，本体带 `Offset 1,1`。
   如果描边的 `shellRadius` 判定有问题，或者描边颜色太深盖住了本体，也会是黑的。

### 我不猜了，加一个调试模式

在材质上加一个 `_DebugMode`：

| 值 | 输出 | 用来确认 |
|---|---|---|
| 0 | 正常 | — |
| 1 | 纯红（全不透明） | **shader 到底有没有在画** |
| 2 | 只看 `col.rgb`，强制 alpha=1 | 颜色算出来是什么 |
| 3 | 只看 `cover`（覆盖率） | 覆盖曲线对不对 |
| 4 | 只看 `specBand` / `rimBand` | 光和法线对不对 |
| 5 | 只看法线 | 法线是不是反的 |
| 6 | 描边画绿色 | 描边和本体各自占了多少 |

**先跑 1 和 5。** 这两条能直接分开"没画出来"和"法线反了"两种完全不同的原因。
这比我继续猜三轮都快。

## 五、顺带看到的两个小问题

1. **通关之后泡泡还在长**（第二张截图左上角是"通关！用时 65.9 秒"）。
   潮水在 `IsFinished` 之后仍然推进 `m_Elapsed`，所以泡泡继续出现。
   看你要不要让它停下 —— 停下的话要加一个"结束后不再推进"的开关。

2. **`33/117 颗  半径 5.79 米`** → 现在只有 117 颗、半径 5.79 米，
   已经接近你要的区间了。但**半径 5.79 米意味着直径 11.6 米**，
   而玩家高度大概 2 米 —— 站在泡泡旁边几乎整个视野都是它。
   所以「挡视线」这件事会很明显，`Spacing Multiplier` 要配合调。
