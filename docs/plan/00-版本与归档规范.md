# 版本与归档规范

## 一、版本号格式

| 对象 | 格式 | 示例 | 说明 |
|------|------|------|------|
| **游戏开发版本** | `X.X.XXX` | `1.0.001` | 三位补零的构建号 |
| **策划案版本** | `vX.XX` | `v1.01` | 两位小版本号 |

### 游戏版本 `X.X.XXX`

```
  1  .  0  .  001
  │     │     └── 构建号（000-999），每次构建 +1
  │     └──────── 次版本号，小型功能迭代
  └────────────── 主版本号，重大里程碑
```

| 变更类型 | 版本变化 |
|---------|---------|
| 修复 bug / 调整数值 | `1.0.001` → `1.0.002` |
| 新增功能 / 关卡 | `1.0.002` → `1.1.000` |
| 重大重构 / 新章节 | `1.1.000` → `2.0.000` |

### 策划案版本 `vX.XX`

```
  v  1  .  01
     │     └── 小版本号（01-99），每次修订 +1
     └──────── 主版本号，方向性变更
```

| 变更类型 | 版本变化 |
|---------|---------|
| 文字修订 / 补充说明 | `v1.01` → `v1.02` |
| 新增章节 / 调整规则 | `v1.05` → `v2.00` |
| **方向性推翻重来** | `v2.00` → `v3.00` |

## 二、归档规则

### 何时归档

**每次「大型更改」后归档一次。** 大型更改指：

- ✅ 核心规则增删（如三条规则变四条）
- ✅ 叙事结构调整（如改变结局）
- ✅ 载体 / 表现层变更（如换美术方向）
- ✅ 关卡数量或结构变化
- ✅ 项目定位变更（如平台切换）

**不算大型更改**（不必归档）：
- ❌ 错别字修正
- ❌ 排版调整
- ❌ 补充个别说明文字

### 归档流程

```
1. 修改正文（03-核心设计.md 等）
2. 更新正文顶部版本号
3. 复制快照到 archive/
4. 在 README 的归档记录中登记
5. 提交
```

### 命名格式

```
archive/{文档名}_v{版本}_{日期}.md
```

示例：
```
archive/03-核心设计_v1.01_2026-10-03.md
archive/03-核心设计_v1.02_2026-10-05.md
archive/03-核心设计_v2.00_2026-10-09.md
```

## 三、目录结构

```
docs/plan/
├── README.md                   索引 + 归档记录
├── 00-版本与归档规范.md         本文件
├── 01-玩法设计.md               早期候选（留档）
├── 02-开发计划.md               里程碑与分工
├── 03-核心设计.md               ⭐ 当前有效稿
└── archive/                    历史快照
    └── 03-核心设计_v1.01_2026-10-03.md
```

**规则**：`archive/` 只读，永不修改。当前稿始终在 `docs/plan/` 根下。

---

## 四、为什么归档

1. **可回溯** — 想不起"当初为什么这么设计"时，翻历史版本
2. **可对比** — 方向变更时，能看清改了什么
3. **可恢复** — 新方向走不通，能退回旧稿
4. **评审用** — 给队友/评委看迭代过程，比只看最终稿更有说服力
