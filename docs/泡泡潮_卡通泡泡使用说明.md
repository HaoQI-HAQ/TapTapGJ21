# 泡泡潮 · 卡通泡泡（性能优化版）说明

> 以 **`PAO/BubbleBall` 为基准**重写的一版，专供「泡泡潮」的大泡泡使用。
> 你原来的 `BubbleBall.shader` / `BubbleBallCore.hlsl` **一个字节都没动**。

## 二、优化了什么（只动了三处，都是等价替换）

### 优化 1：每像素 12 个 sin → 0 个（最大的一笔）

原版 `Frag` 里调了 **4 次 `WobbleAmount`**，每次 3 个 `sin`：

```hlsl
// BubbleBallCore.hlsl 原文 —— 每像素 12 个 sin
if (_NormalWobble > 1e-5)
{
    float3 nOff = float3(
        WobbleAmount(normalize(N + float3(0.08, 0, 0)) * _WobbleFrequency, ...),
        WobbleAmount(normalize(N + float3(0, 0.08, 0)) * _WobbleFrequency, ...),
        WobbleAmount(normalize(N + float3(0, 0, 0.08)) * _WobbleFrequency, ...));
    N = normalize(N + nOff * _NormalWobble);
}
float thickNoise = WobbleAmount(normalize(i.positionOS) * 2.5, ...);   // 第 4 次
```

**本版做法**：在**顶点**里算一次扰动，外加它沿两个切向的梯度（沿切向各偏移一点点求差），
把梯度作为 `float2` 插值下去。片元只读这个值来推法线：

```hlsl
// 顶点
wob = WobbleAmount(dirOS * _WobbleFrequency, t);
float w1 = WobbleAmount(normalize(dirOS + tanV * eps) * _WobbleFrequency, t);
float w2 = WobbleAmount(normalize(dirOS + bitV * eps) * _WobbleFrequency, t);
wobGrad = float2(w1 - wob, w2 - wob) / eps;

// 片元：0 个 sin
N = normalize(N - (tanV * i.wobbleGrad.x + bitV * i.wobbleGrad.y) * 系数);
```

求的是**同一个量**，只是采样率从「每像素」变成「每顶点」。球面保持干净、顶点数不变。
`thickNoise`（膜厚噪声）同样搬到顶点。

### 优化 2：每像素 2 次 cubemap 采样 → 0 次

```hlsl
// 原版：两次采样
float3 cubeRef = _Cube.SampleLevel(sampler_Cube, reflect(-V, N), 0).rgb;
float3 T = refract(-V, N, 0.92);
float3 transCube = _Cube.SampleLevel(sampler_Cube, T, 0).rgb;
```

这两次的贡献分别被压在 `* 0.5` 和 `* _Transmission * 0.5` 之后，本来就很弱，
却要付两次纹理带宽。本版换成**解析的天光渐变**，方向和亮度对齐原版意图。

> `_Cube` 属性**保留着**，材质不会丢引用，只是不再逐像素采样。

### 优化 3：删掉两个没用上的量

| 删掉的 | 为什么 |
|---|---|
| `_SpecPower` | 卡通高光走 `XStep` 阈值，从来没用过这个指数 |
| `_TransmissionTint` | 原版里是个常量色 `(0.85, 0.95, 1.0)`，直接折进公式 |

## 三、故意**没有**动的东西（以及为什么）

前几轮我在这上面反复踩坑，这些都验证过是对的，**不要改**：

| 保留的东西 | 为什么不能动 |
|---|---|
| 三个 Pass 的顺序：`Outline` → `Back` → `Front` | 这是原版能正常显示的关键。把本体挪到描边之后会导致本体被深度测试整片丢弃 |
| `Blend SrcAlpha OneMinusSrcAlpha` + `ZWrite On` | 半透明混合。**颜色再暗也会把后面的东西混出来**，所以不会出现「空洞」 |
| `Cull Front` / `Cull Back` 的分工 | 反向外壳描边 + 背面垫底都靠它 |
| `XStep` 色阶量化 | 卡通观感的骨架 |
| 双色相彩虹、双高光 | 卡通泡泡的识别特征 |

### 两个明确的「不要」

1. **不要用 `[Tooltip]`。**
   本项目里它会触发 ShaderLab 的 `Parse error: ... expecting TVAL_ID`。
   原有 shader 全都只用 `[Header]`，一个 Tooltip 都没有。
   说明文字写在 Properties 块**外面**的注释里。

2. **不要用 `AlphaToMask` + 抖动裁剪来省性能。**
   我试过（用不透明队列 + AlphaToMask 表达半透明），
   结果是材质预览里整颗泡泡消失 —— alpha-to-coverage 在没有 MSAA 的地方行为不可控。
   **半透明混合虽然多花一点填充率，但它是稳定可预期的。**

```
1) 菜单：工具 → PAO → 泡泡潮 → 新建卡通泡泡材质
```

| 参数 | 默认 | 说明 |
|---|---|---|

## 五、本轮新做的四件事

### 1. 位置不再「排队」—— 改成蓝噪声分布

**之前**的 `BuildLayout` 是规则网格：

```csharp
Vector3 center = new Vector3(
    bounds.min.x + (bx + 0.5f) * blockSize.x,
    bounds.min.y + (by + 0.5f) * blockSize.y + m_HeightOffset,
    bounds.min.z + (bz + 0.5f) * blockSize.z);
```

纯网格、零随机、所有泡泡一样大 —— 所以看起来像排队。

**现在**改成 **Poisson-disk 拒绝采样（蓝噪声）**：
在包围盒里撒**远多于需要数量**的候选点（默认最多 6000 个），
逐个检查「离已接受的所有泡泡是否都足够远」，够远才接受。

- 得到的是**均匀但没有周期**的分布 —— 正是气泡堆积的样子，**没有任何网格痕迹**
- 为什么不用便宜的「抖动网格」：抖动量必须小于半格否则会撞在一起，
  所以**周期结构还在**，只能打散「整齐」，打散不了格子的痕迹。
  而拒绝采样对这个量级只要几毫秒，值得

新增参数：

| 参数 | 说明 |
|---|---|
| `泡泡半径` | 整体大小（米）。蓝噪声分布会在这个基础上下浮动 |
| `大小浮动比例` | 0.35 = 半径在 0.65~1.35 倍之间随机。**大球小球混着才有层次** |
| `最小间距系数` | 相对两者半径之和。`<1` 允许重叠 / `1.0` 相切 / **`1.25` 默认** / `1.6+` 明显分开 |
| `边缘留白` | 球心离房间边界至少留多少米。设小一点会让泡泡稍微穿墙，对「挤满」有帮助 |
| `最大采样数` | 蓝噪声靠「撒点+拒绝」，这个数决定能找到多少颗。太小会摆不满 |

### 2. 通关后泡泡不再继续长

`BubbleTideDirector` 在结束之后**仍然会把 `m_Elapsed` 往上加**
（它自己的注释说明了：为了让玩家继续看潮水淹满）。
但泡泡不该跟着长 —— 玩家已经过关了，屏幕上还冒新泡泡很奇怪。

新增开关 **`结束后冻结（Freeze After Finish）`**，默认勾上。
勾上时在结束那一刻把时间钉住，泡泡停在当前进度。

### 3. 颜色随机（底色 + 描边色）

| 参数 | 说明 |
|---|---|
| `颜色随机` | 开关 |
| `随机范围` | `Both` 底色和描边一起换（推荐）/ `BaseOnly` / `OutlineOnly` |
| `随机强度` | 0 = 完全按色板，1 = 等于材质原色（不随机）。默认 0.75 |
| `色板` | 每颗从这里随机取一组（底色 + 描边色）。留空用内置的 6 组浅色 |

**两个设计要点：**

1. **颜色是「乘」上去的，不是覆盖。**
   `最终底色 = 材质底色 × tintA`，`最终描边色 = 材质描边色 × tintB`。
   所以材质上的设置仍然是主体，白色 = 不改变。
   想整体调亮调暗还是去改材质。

2. **底色和描边配成一对，而不是各自独立随机。**
   各自随机会出现「深绿泡泡配亮黄描边」这种撞色，一堆里就有几颗特别跳。
   配成对之后每颗泡泡是一个协调的整体，而你仍然可以逐对去调。

### 4. 每颗泡泡的扰动错开了

原版所有泡泡的扰动**完全同步**（同一时刻、同一波形），
摆一片出去像整齐划一的呼吸，一眼看出是同一个模型复制出来的。
现在把每颗的 `wobbleSeed` 折进扰动相位和膜厚噪声，流动各走各的。

## 六、还没做的（就剩一条）

**启动卡约 10 秒** —— 这个**不用改我的代码**，在 `BubbleTideDirector` 的 Inspector 上就能调：

> **烤制 → 体素边长（Cell Size）：`0.5` → `1.0`**

格数是**立方**关系，所以工作量直接降到 **1/8**（470 万格 → 59 万格）。
代价是潮水边缘变方一点 —— 但这一版的主角是泡泡，
那张表只用来查「第几秒淹到」，边缘精度根本不重要。

顺带把 **障碍物层（Obstacle Mask）** 从 `~0`（所有层）
收窄到只勾「地面/墙」那几层，`Physics.CheckSphere` 会再快一截。

如果 1.0 还是慢，再降到 1.5 或 2.0。**泡泡的布局不依赖格距**，
所以调它不会影响泡泡的位置分布。

## 七、排查经验（留个记录）

1. **ShaderLab 解析错误先读 `Editor.log`**，别只看 Console ——
   Console 可能不给行号、也可能给错行号。
   ```
   %LOCALAPPDATA%\Unity\Editor\Editor.log
   ```

2. **PowerShell 在这个环境里会把 UTF-8 文件当 GBK 读**，
   中文会乱码、引号配对会误报。要用
   `[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)`。

3. **改 shader 渲染方式（比如混合 → 裁剪）时，必须补上不透明物体才需要的着色项**，
   尤其是漫反射底色。混合模式下能省掉的，裁剪模式下省不得。
